# Claude Code Plugin Package

VAD provides a local Claude Code package contract for workspace use. The package is generated by `vad.control_plane.claude_code_package.build_claude_code_package`.

## Package Contract

- Plugin id: `vad-claude-code-local`.
- Target client: `claude_code`.
- Transport: local stdio MCP.
- Workspace config path: `.mcp.json`.
- Command: `vad mcp run`.
- Live services default: `VAD_LIVE_SERVICES=disabled`.
- High-risk tools are never approved by default.

## Local MCP Config

Use this workspace `.mcp.json` shape:

```json
{
  "mcpServers": {
    "vad": {
      "command": "vad",
      "args": ["mcp", "run"],
      "env": {
        "VAD_LIVE_SERVICES": "disabled"
      }
    }
  }
}
```

The generated plugin dry-run also includes a user-scoped preview path at `claude-code/vad-mcp.json` for clients or operators that prefer user-level config review. The dry-run does not write either file.

## VAD Role Prompts

Use these short role prompts when starting Claude Code in a VAD workspace:

- Builder: read the active EIP and proof plan before editing; use VAD MCP tools for repository assessment; keep high-risk writes behind explicit approval.
- Verifier: run the stated proof obligations; inspect evidence; report failures with exact commands and artifact paths.
- Auditor: review policy decisions, signatures, retrospective learnings, and recovery evidence before accepting a run.

## Dry-Run Review

Preview the generated config paths and content before installing:

```bash
vad plugins install path/to/claude-plugin.json --dry-run --workspace-root . --user-config-root ~/.config
```

The package manifest and generated config contain no secrets, tokens, passwords, or cloud endpoint defaults. High-risk tools such as repository patching and signature verification remain hidden unless the caller supplies the matching role and explicit high-risk approval for that call.

## Manual Fallback

Run the MCP server directly when Claude Code cannot consume a config file:

```bash
vad mcp run
```
