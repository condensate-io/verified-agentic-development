# OpenCode Integration Package

VAD provides a local OpenCode package contract generated by
`vad.control_plane.opencode_package.build_opencode_package`. The package is a
dry-run artifact for operator review. It does not write user profile files,
install OpenCode plugins, or approve tools on the operator's behalf.

## Current OpenCode Config Shape

OpenCode supports JSON and JSONC config. The current docs define these standard
locations:

- global config: `~/.config/opencode/opencode.json`;
- project config: `opencode.json` in the project root;
- project `.opencode/` directory for agents, commands, plugins, skills, tools,
  and themes.

The package generates a project `opencode.jsonc` so the review artifact can use
the documented JSONC format and still validate against OpenCode's schema.

## Local MCP Server

OpenCode configures MCP servers under the `mcp` key. Local servers use
`type: "local"` and a command array. The generated VAD config is:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "vad": {
      "type": "local",
      "command": ["vad", "mcp", "run"],
      "enabled": true,
      "environment": {
        "VAD_LIVE_SERVICES": "disabled"
      }
    }
  }
}
```

The package id is `vad-opencode-local`. Installer dry-run output lists the
workspace `opencode.jsonc` file and a user review path
`.config/opencode/opencode.json` under the supplied user config root.

## Agent Tool Gates

OpenCode supports per-agent permissions in both config and Markdown agent files.
The package keeps all VAD MCP tools approval-gated by default with `vad_*: ask`
and then grants narrow safe reads where appropriate.

Generated agents:

- `.opencode/agents/vad-builder.md`: primary builder guidance. Allows
  `vad_validate_eip`, `vad_repo_assess`, and `vad_evidence_inspect`; keeps edit,
  bash, and all other `vad_*` tools on `ask`.
- `.opencode/agents/vad-verifier.md`: subagent verifier guidance. Denies edit,
  allows safe read/evidence tools, and keeps `vad_run_proofs` on `ask`.
- `.opencode/agents/vad-auditor.md`: subagent auditor guidance. Denies edit,
  allows validation/evidence reads, and keeps retrospective writes on `ask`.

High-risk VAD tools such as repository patching are not granted `allow` in any
generated agent. OpenCode may still prompt for them, and VAD's MCP gateway keeps
high-risk tools hidden unless the run explicitly passes approved high-risk tool
names.

## Dry-Run Review

Installer dry-run output lists:

- workspace `opencode.jsonc`;
- workspace `.opencode/agents/vad-builder.md`;
- workspace `.opencode/agents/vad-verifier.md`;
- workspace `.opencode/agents/vad-auditor.md`;
- user review path `.config/opencode/opencode.json`.

Security audit checks reject embedded secret markers, non-local cloud endpoints,
path escapes, and high-risk tools approved by default.

Manual fallback remains:

```bash
vad mcp run
```
