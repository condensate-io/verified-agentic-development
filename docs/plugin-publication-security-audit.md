# Plugin Publication Security Audit

This audit covers the generated local plugin/package artifacts for Codex,
Claude Code, VS Code, Cursor, Windsurf, OpenCode, and generic MCP clients. It
does not approve publication. It is a local artifact review boundary for the
current local Level 4 distribution.

Out of scope and not implemented: marketplace upload, registry upload, public
release distribution, automatic install, automatic trust, automatic high-risk
tool approval, remote plugin registry sync, hosted VAD SaaS publication, or
production signing infrastructure.

## Artifact Scans

Publication review starts from artifacts generated by
`build_reproducible_artifacts`. The builder emits deterministic paths,
per-file SHA-256-style digests, and `digest-report.json`.

Required scan evidence:

- `digest-report.json` exists beside the generated artifacts;
- `secret_scan_passed` is `true`;
- generated plugin manifests are under `plugins/{plugin_id}/{version}/manifest.json`;
- generated schemas include `schemas/vad-plugin-manifest.schema.json`;
- artifact digests are stable across repeated builds;
- generated files reject secret markers such as `api_key`, `token`, `password`,
  `secret`, `private_key`, and provider-style `sk-` values.

The artifact scan is necessary evidence, not a publication approval. A clean
scan means the artifact is reviewable by a human operator.

## Manifest Validation

Every generated plugin manifest must validate as `VADPluginManifest` and remain
bound to the checked-in schema at `schemas/vad-plugin-manifest.schema.json`.

Required manifest evidence:

- semantic version is explicit, not `latest`;
- target client is one of the supported local client types;
- command defaults to local `vad mcp run`;
- command environment is non-secret;
- config paths are relative and scoped to user or workspace review paths;
- permissions, tool grants, prompts, and checksums are unique;
- checksum values are 64-character lowercase hexadecimal digests;
- artifact hash binds `plugin_id`, `version`, manifest digest, and file
  digests.

Schema validation and artifact hashing do not install or trust a plugin. They
only prove the manifest is structurally reviewable.

## No Auto-Trust Or Auto-Approval

No generated plugin artifact is trusted automatically. Dry-run installer output
must report `dry_run=True`, `writes_performed=0`, exact planned config paths,
and rollback metadata using `restore_or_remove`.

High-risk MCP tools must not be approved by default. This includes:

- `repo_patch`
- `repo_run`
- `sign_verify`

The manifest model rejects high-risk tool grants with
`approved_by_default=True`, and `audit_plugin_artifact_security` reports
`dangerous_auto_approval` if a tainted artifact bypasses that model boundary.

No artifact scan, manifest validation, dry-run, dashboard status, package
status, or publication decision record is a substitute for explicit human approval.
`docs/publication-decisions.md` is a decision record only; it does not publish
packages or mark marketplace acceptance complete.

## Local-Only Defaults

Generated plugin artifacts are local by default:

- commands use `vad mcp run`;
- MCP transport is stdio unless a reviewed local control-plane route is used;
- default config snippets must not contain cloud endpoints;
- generated package metadata must not include live provider credentials;
- no artifact may include API keys, tokens, passwords, signing secrets, private
  keys, or provider credentials;
- install review uses temp workspace/user config roots and dry-run output
  before any human copies config into a real client.

`audit_plugin_artifact_security` reports `no_cloud_default` when a manifest or
generated dry-run config contains a non-local HTTP endpoint. Local-only defaults
do not mean production ready; they mean the artifact is bounded to operator
review on the local machine.

## Residual Limitations

- The current local distribution does not upload to PyPI, npm, VS Code Marketplace, OpenVSX, Claude
  plugin marketplace, or any remote registry.
- Local development signatures are review evidence only, not production key
  management.
- Antigravity remains a generic MCP fallback until a documented local
  integration/package surface exists.
